## 指摘分類の定義

- 停止指摘: 完了条件または品質基準を満たさないため修正が必須の指摘（監査SAが産出）。
- 任意指摘: 今回の完了を妨げない改善。修正は任意。
- 範囲外指摘: 今回の作業単位（単位1・単位2・追補3）では扱わない範囲外の指摘（例: 承認事項6の英語句）。
- 重大指摘: PRレビュー相当でブロッカーとなる指摘（レビューSAが産出）。
- 改善指摘 / 補足: レビューSAの非ブロッカー指摘。自動修正しない。レビューSAの範囲外指摘も自動修正しない。

## SA起動順・自動修正ループ

1. 実装SA起動（ロールプロンプト=`.agents/prompts/implement.md` を明示、禁止操作を明示）。単位1→単位2→追補3を通しで実装、または追補3を単位2に先行させて整合。
2. 監査SA起動（ロールプロンプト=`.agents/prompts/audit.md` を明示）。渡す内容は「本指示書・差分・テスト結果（=done機械検証の結果）・関連仕様（PG §書き味ポリシー）」のみ。実装経緯・背景・親エージェントの事前評価は渡さない。
3. 監査SAの停止指摘0件を確認後、レビューSA起動（ロールプロンプト=`.agents/prompts/review.md` を明示）。非破壊でPRレビュー相当の品質確認を行う。

### 自動再修正の可否条件と停止条件

- 自動再修正の対象は、承認済み範囲に直接対応する停止指摘または重大指摘のみ。
- レビューSAの重大指摘は、承認済み範囲内かつ最小修正可能な場合に限り自動修正候補とする。改善指摘・補足・範囲外指摘は自動修正しない。
- 監査SA・レビューSAの指摘は、親が作業単位化し直してから実装SAへ渡す。
- 自動修正ループ上限: 5回。
- ループ中の停止条件: 上限5回到達 / 作業単位化できない停止指摘または重大指摘 / 重大指摘・停止指摘の原因特定未了 / 同一原因への再修正が2回連続で失敗。
