## 書き味ポリシーの内容仕様（段階1で文書化するもの）

新セクション「## 書き味ポリシー」は以下の6領域で構成する。対象はAI制御文書（`AGENTS.md` / `.agents/prompts/*.md`）。症状例・事故ログは書かず、規則として抽象化して書く。ポリシー自身がポリシーに準拠した書き味であること。

### 領域1: 用語規範（一概念一語の用語集）
「正規形 / 禁止される異表記 / 定義の置き場所」の3列の表。最低限含める行:
- プランSA / 実装SA / 監査SA / レビューSA（正規形。異表記=「プランサブエージェント」等のフル表記の本文使用。定義=使用する各文書の冒頭略語行）
- 親エージェント（異表記=無定義の「親」単独使用。略語行で「親=親エージェント」を定義した文書内では「親」可）
- 指示書作成（異表記=Planning。英語工程名を使わない）
- ロールプロンプト（異表記=前後強調スペース付き表記、英語「role prompt」※対象5ファイル内）
- PRレビュー（異表記=「PR レビュー」）
- ドキュメント（異表記=地の文の「doc」）
- 品質基準（異表記=基準を指す文脈での「品質」単独）
- 親エージェントの事前評価（異表記=「呼び出し元の事前評価」「呼び出し元評価」「親の事前評価」）
- 親エージェントへの引き継ぎ事項（異表記=宛先なしの「引き継ぎ事項」）
- 停止指摘 / 任意指摘 / 範囲外指摘 / 重大指摘 / 改善指摘 / 補足（定義の置き場所: `AGENTS.md`=親向け、各ロールプロンプト=自分が産出する分類のみ冒頭または該当セクションで定義）
- AI制御文書（異表記=「AI 制御文書」〔半角スペース入り〕。段階1補遺で追加: 領域5手続き〔用語集更新が先、使用が後〕に基づく。監査SA・レビューSAの引き継ぎ事項に由来）
- 書き味ポリシー（異表記=なし。`docs/how-to/agents-prompt-guide.md` §書き味ポリシー を指す参照名。段階1補遺で追加）

### 領域2: 略語・英語工程名の使用規則
- 自己完結を謳う文書（ロールプロンプト4本）では、使用する略語（SA等）は文書冒頭の定義行で定義してから使う。無定義の略語使用は禁止。
- 英語工程名は使わず和語を用いる（例: 指示書作成）。
- `AGENTS.md` 冒頭の略語定義は `AGENTS.md` 内でのみ有効。他文書へ波及させない。

### 領域3: 記号・空白規則
- 強調スペース禁止（語の前後に半角スペースを置かない）。
- 数値と助数詞は続け書き（「0件」「5回」「上限5回」）。語と数値の間にスペースを置かない（「停止指摘0件」）。
- コードスパンと和文の間は半角スペース1つ（句読点・括弧・中黒などの全角記号と隣接する場合はスペースを置かない）。
- スラッシュ列挙は「A / B / C」（前後半角スペース付き）。「・」による列挙は可（変換しない）。
- ファイル名・パス・ディレクトリ・コマンド・キー名（`target / scope / done / tests / stop` 等）は常にコードスパン（バッククォート）。
- 空行は最大1行（連続空行禁止）。見出し直前は空行1行、直後は空行なし。ファイル末尾は改行1つ。
- スラッシュ列挙の直後に助詞を介さず名詞が続く場合、列挙境界を示す半角スペースを置く（機能的スペースとして許容。例:「停止指摘 / 任意指摘 / 範囲外指摘 分類」）。
- 全角スラッシュ「／」は対比表現にのみ許容し、列挙には使わない。
- 裸の欧文語と和文の間は半角スペース1つ（例:「境界を AI が選ぶ」）。
- セクション参照（§名）は和文として扱い、後続の和文・助詞との間にスペースを置かない（直前のコードスパンとの間はコードスパン規則に従う）。

### 領域4: 文体の型
- ロールプロンプト冒頭（§役割 第1項目）は「何をするか（責務）」を書く。「誰が使うか（利用経路）」は正本（`docs/how-to/agents-orchestration-process.md`）側に置く。
- 文の箇条書きは終止形+句点（「〜する。」「〜しない。」）。名詞列挙は句点なし体言止め。同一リスト内の同種項目間での文体不統一を禁止する（文項目は常に句点必須。定義文・注記を含む名詞列挙リストでは、項目種別の混在自体は許容する）。
- ロールプロンプトの標準セクション順は 役割→入力→ルール→出力 を基本骨格とし、固有セクションはその間に置く（推奨）。

### 領域5: 新語・新文書追加時の手続き（再発防止）
- 新しい用語・略語・表記・文書をAI制御文書に導入する場合、先に本ポリシーの用語集・規則を更新し、その後に使用する（ポリシー更新が先、使用が後）。
- 本ポリシーに載らない新語の使用は、AI制御文書変更の監査・レビューで指摘対象となる。

### 領域6: 自己完結性・内容境界の規則
6-1. ロールプロンプトが持ってよい知識（限定列挙）:
  1. 自分の責務・禁止操作・停止条件
  2. 自分への入力の形式と前提条件（入力に他SAの成果物が含まれる場合、その成果物の形式・前提条件を記述してよい）
  3. 自分の出力の形式と宛先（親エージェントが要求する出力フィールド名を含む）
  4. 自分が読んでよいリポジトリ文書の限定列挙と読取条件
  5. 自分の判定基準で使用する分類名とその定義（自分が産出する分類に限る）
6-2. ロールプロンプトが持ってはならない知識:
  1. 他SAの責務・役割の定義（役割差別化は「自分がしないこと」の自己境界として書く）
  2. 自分・他SAの起動順序・起動条件（順序保証が必要なら入力の前提条件として表現する）
  3. 親エージェントのループ制御・回数管理・完了判定・自動修正の成立条件の定義（ロールプロンプトは所見・候補性を出力フィールドとして返すに留める）
  4. 他SAのロールプロンプトのパス（プランSAの例外は6-3）
  5. 自分が産出しない分類体系の定義（混入禁止ルールに必要な範囲で分類名への言及のみ許容）
6-3. 例外:
  - プランSA（`plan.md`）は指示書の設計者として、指示書テンプレート知識（各SAへ渡す内容の項目名・他SAロールプロンプトのパス・全SA分類の定義・親エージェントの停止条件/ループ条件の設計材料）を保持してよい。他SAの責務定義そのものは保持しない。
  - `AGENTS.md` は親エージェント向け契約であり、全SAの起動順序・分類管理・完了判定の知識を持つことが責務。逆にSA内部の作業手順詳細は持たない。
6-4. 他文書参照の作法:
  - ロールプロンプトは、内容の委譲を目的とした `docs/how-to/agents-orchestration-process.md` / `docs/how-to/agents-prompt-guide.md` への参照（「詳細は〜を参照」型）を持たない（自己完結原則）。ただし6-1の4の読取対象の限定列挙として、読取条件付きで特定セクション（例: `docs/how-to/agents-prompt-guide.md` §書き味ポリシー）を参照する場合を除く。
  - リポジトリ文書（正本ドキュメント）への参照は6-1-4の「自分の読取対象の限定列挙」としてのみ持つ。
  - 越境知識をロールプロンプトに追加したくなった場合、まず「入力の前提条件」「出力フィールド」「自己境界」のいずれかへ変換できないか確認する。

## 監査・レビューの判定基準（全段階共通）
- 監査観点: (a) ポリシー違反の残存有無 (b) 意味・境界・責務・分類基準が指示書のscopeを超えて変わっていないか (c) 対象外変更・便乗改善の混入 (d) 変更後文書全体の自己無矛盾（AI制御文書のため差分だけでなく全文を読む）。
