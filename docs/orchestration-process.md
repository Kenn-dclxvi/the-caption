# Agents Orchestration Process
## 目的
この文書は、THE-CAPTION における AI 駆動開発プロセスの運用仕様を定義する。

対象は、ChatGPTまたはプランサブエージェントによる計画作成、Codex / Claude Code による親エージェント運用、実装サブエージェント、監査サブエージェント、レビューサブエージェントの関係である。

この文書は、アプリケーション仕様ではなく、開発環境における AI エージェント運用プロセスの仕様である。

## 基本方針
AI 駆動開発プロセスは、以下の責務分離を前提にする。

```text
指示書作成（ChatGPTまたはプランサブエージェント）
  ユーザー依頼を整理し、実装指示書を作成する。

親エージェント（Codex / Claude Code）
  承認済み実装指示書を理解し、実行状況を管理する。

実装サブエージェント
  実装を行う。

監査サブエージェント
  非破壊で監査を行う。

レビューサブエージェント
  PRレビュー相当の品質レビューを非破壊で行う。
```

親エージェントは、承認済み実装指示書または明示された作業単位化条件がある場合に限り、実装サブエージェントを起動する。依頼を `target / scope / done / tests / stop` に分解できない場合、または分解に AI 側の補完が必要な場合は停止する。最新ユーザー入力は、承認済み実装指示書と矛盾しない範囲でのみ作業単位候補の整理に使う。

ユーザーは、草案が明示条件を満たすなら追加確認なしで作業単位化して実行してよい、という条件付き事前承認を先に宣言できる。条件付き事前承認は、条件・対象・範囲・完了条件・品質基準・実行許可が明示され、条件充足を推定で判断せず確認できる場合だけ作業単位化条件として扱う。AI は条件・対象・範囲・完了条件・品質基準・実行許可を補完してはならない。条件充足を推定で判断する必要がある場合は停止する。`commit` / `push` / `deploy` / 外部送信は、別途明示許可がない限り条件付き事前承認に含めない。

親エージェントは、実装・修正・テスト実行・監査・監査後のPRレビュー相当の品質確認を直接行わない。指示書作成も直接行わず、ユーザーが指示書作成を明示依頼した場合に限りプランサブエージェントを起動する。調査・参照・仕様確認・判断は親が直接行う。サブエージェントに調査を丸投げしない。

明示された文書・差分の非破壊レビュー依頼は、親エージェントが直接扱える。ただし、監査SAの停止指摘0件後に行うPRレビュー相当の品質確認工程はレビューSA専管とし、親エージェントは直接実行しない。

親エージェントは、承認済み実装指示書、明示されたロールプロンプト、差分、テスト結果、監査結果、レビュー結果を管理し、次のアクションを判断する。

## SA利用ケース
親エージェントがサブエージェントを起動するのは以下6ケースに限定する。それ以外は親が直接処理する。

| # | ケース | 目的 |
|---|---|---|
| A | プロンプト・コマンドの実行確認 | 副作用を隔離し、親のコンテキストを汚染しない |
| B | 独立した作業単位のパラレル実行 | 独立性基準を満たす作業単位を同時進行する |
| C | 事前知識なし監査 | 文脈汚染のない視点で差分・仕様を照合する |
| D | 製造→監査→レビュー→修正 自動ループ | 停止指摘 / 重大指摘0件になるまで反復改善する |
| E | 指示書草案作成 | ユーザーが指示書作成を明示依頼したときに限り、plan.md に従い草案を作る |
| F | PRレビュー相当の品質レビュー | 監査SA通過後に、コード品質・設計・テスト妥当性を非破壊で確認する |

ケースEは、ユーザーが指示書作成を明示依頼した場合に限り起動する。親が「指示書化が必要」と推定して起動しない。プランSAの出力は草案であり、実行許可ではない。

## 指示書作成
### 実行者
指示書作成は、ChatGPTまたはプランSA（ケースE）が実行する。

親エージェントは指示書作成を直接実行しない。ユーザーが指示書作成を明示依頼した場合に限り、`prompts/plan.md` をロールプロンプトとして渡してプランサブエージェントを起動し、指示書作成を担わせる。

### 役割
指示書作成は、ユーザー依頼を実装指示書へ変換する。

指示書作成は実装を行わない。
指示書作成は監査を行わない。
指示書作成はレビューを行わない。
指示書作成は再修正ループを実行しない。
指示書作成は実行許可を生成しない。

指示書作成は、後続工程で親エージェントが実装サブエージェント、監査サブエージェント、レビューサブエージェントを起動し、自動再修正の可否を判断できるように、実装指示書へ必要な情報を含める。
指示書作成は、実装・監査・レビュー・再修正ループの設計材料を実装指示書に含める。
指示書作成の出力は後続工程へ渡すための実装指示書であり、それ自体は実装・修正・テスト実行・監査・レビュー・自動再修正の許可ではない。

### 使用プロンプト
```text
prompts/plan.md
```

### 入力
- ユーザー依頼
- 必要に応じて参照された仕様・設計・既存文書
- 直前までに承認された方針

### 出力
指示書作成は、境界が十分に明確な場合、実装指示書を作成する。

実装指示書には以下を含める。

- 目的
- 前提
- 変更対象
- 変更範囲
- 変更しない範囲
- 完了条件
- テスト条件
- 実装サブエージェントへの指示
- 監査サブエージェントへの指示
- 監査対象
- 監査観点
- 停止指摘 / 任意指摘 / 範囲外指摘の判定基準
- レビューサブエージェントへの指示
- レビュー対象
- レビュー観点
- 重大指摘 / 改善指摘 / 補足 / 範囲外指摘の判定基準
- 自動再修正してよい条件
- 自動再修正してはいけない条件
- レビューSAの重大指摘の自動再修正条件
- レビューSAの重大指摘由来の停止条件
- 親エージェントの停止条件
- 承認済み実装指示書として扱うために必要な条件
- 指示書作成出力が実行許可ではないこと
- 親エージェントの最終出力契約
- 自動再修正ループの上限
- 同一の停止指摘再発時の停止条件
- 同一原因に対する再修正失敗時の停止条件

### 禁止事項
指示書作成は以下を行わない。

- 実装
- 修正
- ファイル作成
- ファイル削除
- ファイル移動
- テスト実行
- 監査
- レビュー
- 実行許可の生成
- 対象・範囲・完了条件・品質基準の補完
- 実装・監査・レビュー・再修正ループの実行

承認済み実装指示書とは、最新ユーザー入力で実行対象として明示され、既存の承認済み実装指示書と矛盾しない実装指示書である。
指示書作成が作成しただけの指示書は承認済みではない。
会話上で提示されただけの指示書は承認済みではない。
過去に作成された指示書は、最新ユーザー入力で明示され、かつ既存の承認済み実装指示書と矛盾しない場合に限り承認済みとして扱う。

不足項目がある場合は、実装指示書化せず、不足項目を返す。

## 親エージェント（Codex / Claude Code）
### 役割
親エージェント（Codex / Claude Code）は、AI 駆動開発プロセスのオーケストレーターである。

親エージェントは、承認済み実装指示書または承認済み実装指示書と矛盾しない作業単位化対象の最新ユーザー入力を読み、まず委任可否を判断し、実装サブエージェント、監査サブエージェント、レビューサブエージェントを起動し、結果を管理する。

### 使用する制御
```text
AGENTS.md
```

AGENTS.md は、親エージェント用の orchestration gate として扱う。

### 責務
親エージェントは以下を行う。

- ユーザー指示を受ける
- 承認済み実装指示書または承認済み実装指示書と矛盾しない作業単位化対象の最新ユーザー入力を読む
- 依頼をまず委任可能か判断する
- 明示された文書・差分の非破壊レビュー依頼を、明示対象に限り直接扱う
- target / scope / done / tests / stop に分解できる場合は、実装サブエージェント向けに整理して起動する
- 対象・範囲・完了条件・テスト条件（テストコマンドまたは `なし（根拠）`）・監査観点・停止条件を把握する
- 実装サブエージェントを起動する
- 監査サブエージェントを起動する
- 監査SAの停止指摘0件後、必ずレビューサブエージェントを起動する
- 実装結果、テスト結果、監査結果、レビュー結果を受け取る
- 停止指摘 / 任意指摘 / 範囲外指摘を確認する
- 停止指摘が承認済み範囲内なら、実装サブエージェントへ再修正を依頼する
- 任意指摘 / 範囲外指摘を自動修正対象から外す
- レビューSAの重大指摘 / 改善指摘 / 補足 / 範囲外指摘 分類を確認する
- レビューSAの重大指摘が承認済み範囲内で最小修正可能なら、自動再修正候補として扱う
- レビューSAの改善指摘 / 補足 / 範囲外指摘を自動修正対象から外す
- レビューSAの重大指摘は親が作業単位化し直してから実装サブエージェントへ渡す
- 同一の停止指摘が再修正後も再発した場合は停止する
- 同一の重大指摘が再修正後も再発した場合は停止する
- 同一原因に対する再修正が 2回連続で失敗した場合は停止する
- 原因不明または指示書不足を推定で埋めて継続しない
- 範囲外、仕様変更、テスト期待値変更、原因不明の場合は停止する
- 条件付き事前承認の条件充足を推定で判断する必要がある場合は停止する
- 最終結果をユーザーへ返す

### 出力
親エージェントは最終結果として以下を返す。

- 実装結果
- 変更ファイル
- 実行テスト
- テスト結果
- 監査結果
- レビュー結果
- 停止指摘の有無
- 停止指摘は監査サブエージェントの出力から引用し、自動再修正可否の判定根拠として明示する
- 重大指摘の有無
- 重大指摘はレビューサブエージェントの出力から引用し、自動再修正可否の判定根拠として明示する
- 実装サブエージェントを起動しなかった場合は、その理由
- 自動再修正を実行した場合は、その回数と理由
- 停止した場合は、停止理由
- 任意指摘 / 範囲外指摘がある場合は、自動修正しなかった理由
- 改善指摘 / 補足 / 範囲外指摘がある場合は、自動修正しなかった理由
- 未要求の追加提案、次作業提案、便乗改善提案は含めない

### 禁止事項
親エージェントは以下を直接行わない。

- 実装
- 修正
- テスト実行
- 監査
- 監査後のPRレビュー相当の品質確認
- テスト期待値変更
- 仕様変更
- 範囲外変更
- 便乗改善
- 対象・範囲・完了条件・品質基準の補完

### サブエージェント起動
親エージェントは、サブエージェント起動時に、そのSAに対応するロールプロンプトを明示的に渡す。ロールプロンプトは `prompts/` 配下に置く（プランSA=`plan.md` / 実装SA=`implement.md` / 監査SA=`audit.md` / レビューSA=`review.md`）。SA種別が増えた場合も、対応するロールプロンプトを明示する原則は変わらない。

サブエージェントがリポジトリ上の `AGENTS.md` を自動読込する前提にしない。

サブエージェント起動時は、必要な情報を起動メッセージに含める。

- ロールプロンプトの本文または要約
- 承認済み実装指示書または実装サブエージェント起動用の作業指示一式
- target / scope / done / tests / stop に整理した変更対象・変更範囲・完了条件・テスト条件・停止条件
- 監査観点
- レビュー観点
- 禁止操作（scope外編集・git push/force・本番接続・外部送信）

### パラレル起動の独立性基準
パラレル起動は以下をすべて満たす場合のみ可。独立性判定は親エージェントが行う。

1. 変更対象ファイルに重複がない
2. 実行順序の依存関係がない
3. 共有リソースへのアクセスが重複しない

途中で独立性が崩れた場合は後発サブエージェントを停止し、先発サブエージェント完了後に直列で再起動する。

## 実装サブエージェント
### 役割
実装サブエージェントは、承認済み実装指示書に従って実装する。

### 使用プロンプト
```text
prompts/implement.md
```

実装サブエージェントは、`implement.md` を自己完結した実装契約として扱う。

### 入力
- `implement.md` の本文または要約
- 承認済み実装指示書
- 明示された変更対象
- 明示された変更範囲
- 明示された完了条件
- 明示されたテスト条件（テストコマンドまたは `なし（根拠）`）
- 停止条件

### 責務
実装サブエージェントは以下を行う。

- 承認済み実装指示書を読む
- 明示された変更対象だけを変更する
- 明示された範囲だけを変更する
- 明示された完了条件だけを満たす
- 明示されたテスト条件がテストコマンドなら、そのコマンドだけを実行する
- 明示されたテスト条件が `なし（根拠）` なら、テスト実行しない
- 明示されたテストが失敗した場合、既存ログ・テスト出力・関連ファイルを確認し、原因が承認済み範囲内に特定できた場合だけ最小修正する
- 原因が特定できない場合、または承認済み範囲外の場合は、探索的修正をせず停止理由として返す
- 結果を親エージェントへ返す

### 禁止事項
実装サブエージェントは以下を行わない。

- 指示書外の改善
- 仕様変更
- テスト期待値の都合のよい変更
- 対象外ファイル変更
- 便乗リファクタ
- 命名変更
- 移動
- 削除
- 構成変更
- 原因不明の探索的修正
- 実装指示書にないテスト実行

### 出力
実装サブエージェントは以下を返す。

- 実施内容
- 変更ファイル
- 実行したテスト
- テスト結果
- 初回実装か再修正か
- 再修正時の指摘
- 停止理由がある場合は停止理由
- 親エージェントへの引き継ぎ事項

## 監査サブエージェント
### 役割
監査サブエージェントは、実装完了前の全体整合チェック（契約照合 + doc同期確認）を非破壊で行う。

監査サブエージェントは修正しない。

監査SAの役割分担：
- 監査SA = 抜け漏れ・同期漏れ・スコープ逸脱・対象外混入の検出（契約上あるべきもの／あるべきでないものを照合する）
- レビューSA = 品質・設計・保守性の改善提案（あるものをより良くする）

### 使用プロンプト
```text
prompts/audit.md
```

監査サブエージェントは、`audit.md` を自己完結した監査契約として扱う。

監査サブエージェントは、リポジトリ上の `AGENTS.md` を起動時に自動読込する前提にしない。

### 入力
監査SAへ渡してよい情報：

- `audit.md` の本文または要約
- 承認済み実装指示書
- 差分
- テスト結果
- 必要に応じて関連仕様

監査SAへ渡してはいけない情報（事前知識なし監査を保証するため）：

- 実装経緯・背景
- 親エージェントの事前評価・解釈
- 「この点は問題ない」等の先入れ判断

コード変更を含む差分がある場合、監査SA自身が `docs/reference/system.md` と `docs/reference/logic.md` を読む（渡し側ではなく監査SA自身の責務）。

### 責務
監査サブエージェントは以下を行う。

- 非破壊で監査する
- 承認済み実装指示書と差分を照合する
- テスト結果を確認する
- 対象外変更を検出する
- 便乗改善を検出する
- 仕様変更混入を検出する
- テスト期待値変更を検出する
- コード変更を含む差分がある場合、`docs/reference/system.md` および `docs/reference/logic.md` を読み、変更内容と記述が同期しているかを確認する。同期漏れ（コードが変わったのにドキュメントが古いまま）は停止指摘とする（ドキュメントのみの変更にはこのチェックは不要）
- AI制御文書（`AGENTS.md` / `prompts/*.md` / `docs/orchestration-process.md` / `docs/prompt-guide.md`）が変更対象の場合、変更後の文書全体が自己無矛盾かを検査する（差分箇所だけでなく、変更が他セクションへ追従しきれているか・限定列挙の追従漏れがないかを含む）
- 指摘を停止指摘 / 任意指摘 / 範囲外指摘に分類する
- 結果を親エージェントへ返す

### 禁止事項
監査サブエージェントは以下を行わない。

- ファイル変更
- 修正
- テスト実行
- 実装
- 実装指示書作成
- 仕様変更
- テスト期待値変更

### AGENTS.md を読む例外
監査サブエージェントは、通常監査では `AGENTS.md` 実ファイルを読む前提にしない。

ただし、以下の場合は `AGENTS.md` を明示的に監査対象へ含める。

- `AGENTS.md` が変更対象に含まれる
- `prompts/*.md` が変更対象に含まれる
- `docs/orchestration-process.md` / `docs/prompt-guide.md` が変更対象に含まれる
- 実装指示書が `AGENTS.md` 互換性確認を明示している

この場合、差分箇所だけでなく変更後の `AGENTS.md` 全体を読み、変更が他セクションへ追従しきれているか（限定列挙・成立条件・分類基準の追従漏れがないか）を検査する。

### 出力
監査サブエージェントは以下を返す。

- 結論
- 監査対象
- 停止指摘
- 任意指摘
- 範囲外指摘
- 自動修正候補性
- 再監査が必要な条件

## レビューサブエージェント
### 役割
レビューサブエージェントは、監査SAの停止指摘0件後に必ず起動され、PRレビュー相当の品質レビューを非破壊で行う。

レビューサブエージェントは修正しない。

レビューサブエージェントは、監査SAの契約準拠責務を置き換えない。

### 使用プロンプト
```text
prompts/review.md
```

レビューサブエージェントは、`review.md` を自己完結したレビュー契約として扱う。

レビューサブエージェントは、リポジトリ上の `AGENTS.md` を起動時に自動読込する前提にしない。

### 入力
レビューSAへ渡してよい情報：

- `review.md` の本文または要約
- 承認済み実装指示書
- 差分
- テスト結果
- 監査サブエージェントの結果（停止指摘0件）
- 必要に応じて関連仕様

レビューSAへ渡してはいけない情報：

- レビュー結果の分類を先入れする親エージェントの事前評価
- 実装サブエージェントへ直接渡す修正用の作業指示一式
- レビューSAの出力を自動修正許可として扱う指示

### 責務
レビューサブエージェントは以下を行う。

- 非破壊で PRレビュー相当の品質レビューを行う
- コード品質、設計、テスト妥当性、保守性、実行時リスクを確認する
- 重大指摘 / 改善指摘 / 補足 / 範囲外指摘に分類する
- 重大指摘が承認済み範囲内で最小修正候補になりうるかを理由付きで示す
- 改善指摘 / 補足 / 範囲外指摘が自動修正対象ではないことを明示する
- 結果を親エージェントへ返す

### 禁止事項
レビューサブエージェントは以下を行わない。

- ファイル変更
- 修正
- テスト実行
- 実装
- 実装指示書作成
- 監査SAの停止指摘 / 任意指摘 / 範囲外指摘 分類変更
- 改善指摘 / 補足 / 範囲外指摘を自動修正対象として扱うこと
- 実装サブエージェントへ直接修正指示を出すこと

### AGENTS.md を読む例外
レビューサブエージェントは、通常レビューでは `AGENTS.md` 実ファイルを読む前提にしない。

ただし、以下の場合は `AGENTS.md` を明示的にレビュー対象へ含める。

- `AGENTS.md` が変更対象に含まれる
- `prompts/*.md` が変更対象に含まれる
- `docs/orchestration-process.md` / `docs/prompt-guide.md` が変更対象に含まれる
- 実装指示書が `AGENTS.md` 互換性確認を明示している

この場合、変更後の `AGENTS.md` 全体を読み、PRレビュー相当の観点で文書の品質・整合性・限定列挙の追従漏れを確認する。

### 出力
レビューサブエージェントは以下を返す。

- 結論
- レビュー対象
- 重大指摘
- 改善指摘
- 補足
- 範囲外指摘
- 重大指摘の自動修正候補性と理由
- 停止理由
- 親エージェントへの引き継ぎ事項

## 指摘分類
この章の停止指摘 / 任意指摘 / 範囲外指摘は、監査サブエージェントの指摘分類である。
レビューサブエージェントは別分類として重大指摘 / 改善指摘 / 補足 / 範囲外指摘を使い、詳細は `prompts/review.md` と本書の「レビューサブエージェント」章に従う。
レビューSAの改善指摘 / 補足 / 範囲外指摘は自動修正対象にしない。

### 停止指摘
停止指摘は、完了条件または品質基準を満たさないため、修正が必須な指摘である。

例:

- 完了条件未達
- 変更範囲違反
- 対象外ファイル変更
- 仕様変更混入
- テスト期待値の不適切変更
- 実装指示書との矛盾
- 承認済み範囲外の修正
- 原因不明の修正

停止指摘は、承認済み実装指示書の範囲内に直接対応する場合だけ、自動修正依頼の対象にできる。

### 任意指摘
任意指摘は、今回の完了を妨げない改善であり、修正は任意である。

任意指摘は自動修正しない。

### 範囲外指摘
範囲外指摘は、今回の実装指示書の範囲外であり、今回の作業単位では扱わない指摘である。

例:

- 将来対応
- 仕様拡張
- 設計変更
- 別機能の改善
- 任意リファクタ

範囲外指摘は自動修正しない。

## 自動修正ループ（ケースD）
製造（初回実装）→ 監査（監査SA）→ レビュー（レビューSA）を行い、停止指摘または重大指摘が残る場合だけ、修正（実装SA）→ 再監査 → 再レビューを反復する。

初回実装は回数に含めず、自動再修正試行だけを最大5回まで数える。監査SAの停止指摘0件かつレビューSAの重大指摘0件になった時点で終了し、5回目の自動再修正後も停止指摘または重大指摘が残る場合は停止する。6回目の自動再修正は開始しない。

親エージェントは、以下の手順で自動修正ループを管理する。

```text
1. 承認済み実装指示書を確認する
2. 実装サブエージェントを起動する（製造）
3. 実装結果とテスト結果を受け取る
4. 監査サブエージェントを起動する（監査）
5. 監査結果を受け取る
6. 停止指摘を確認する
7. 停止指摘がある場合は、承認済み範囲内かを確認する
8. 停止指摘が承認済み範囲内の場合は、親が停止指摘を解釈して作業単位化し直す
9. 修正用の作業指示一式を実装サブエージェントへ渡す（修正）
10. 再テスト結果を受け取る
11. 再監査する
12. 停止指摘0件になった場合、レビューサブエージェントを起動する（レビュー）
13. レビュー結果を受け取る
14. 重大指摘を確認する
15. 重大指摘が承認済み範囲内かつ最小修正可能な場合は、親が重大指摘を解釈して作業単位化し直す
16. 修正用の作業指示一式を実装サブエージェントへ渡す（修正）
17. 再テスト結果を受け取る
18. 再監査する
19. 停止指摘0件後に再レビューする
20. 停止指摘と重大指摘がなくなるまで、承認済み範囲内でのみ反復する（自動再修正試行は最大5回）
21. 停止条件に該当した場合は停止する
```

- ループ制御・回数カウント・上限判定は親エージェントが管理する。サブエージェントはループ回数を知らなくてよい。
- 初回実装、初回監査、初回レビューは自動再修正試行回数に含めない。
- 監査SAの停止指摘対応、レビューSAの重大指摘対応のどちらも、実装SAへ修正を依頼した時点で自動再修正試行1回として数える。
- 監査SAの停止指摘出力は親が解釈して作業単位化し直してから実装SAへ渡す。直接渡さない。
- レビューSAの重大指摘は親が解釈して作業単位化し直してから実装SAへ渡す。直接渡さない。
- 全停止指摘と重大指摘を自動ループ候補とする。ただし作業単位化できない停止指摘 / 重大指摘（scope外・設計変更要）は停止条件。
- レビューSAの改善指摘 / 補足 / 範囲外指摘は自動修正しない。
- 5回目の自動再修正後も停止指摘または重大指摘が残る場合は、残存停止指摘 / 重大指摘の一覧・ループ経緯をユーザーへ報告して停止する。

同一の停止指摘が連続2回再発した場合、親エージェントは原因不明または指示書不足の可能性があるものとして扱い、推定で継続しない。
同一の重大指摘が連続2回再発した場合、親エージェントは原因不明または指示書不足の可能性があるものとして扱い、推定で継続しない。
自動再修正試行が5回に達し、停止指摘または重大指摘が残る場合も停止する。

### 自動修正してよい条件
以下をすべて満たす場合のみ、自動修正依頼を出してよい。

- 指摘が監査SAの停止指摘またはレビューSAの重大指摘である
- 原因が承認済み実装指示書の対象内である
- 修正対象が承認済み変更範囲内である
- 修正が完了条件を変更しない
- 修正が仕様を変更しない
- 修正がテスト期待値を変更しない
- 修正が便乗改善を含まない
- 最小変更で対応できる
- レビューSAの重大指摘の場合、改善指摘 / 補足 / 範囲外指摘ではないことを親が確認している

### 停止条件
以下の場合、親エージェントは自動修正ループを停止する。

- 指摘が任意指摘である
- 指摘が範囲外指摘である
- レビューSAの指摘が改善指摘である
- レビューSAの指摘が補足である
- レビューSAの指摘が範囲外指摘である
- レビューSAの改善指摘 / 補足 / 範囲外指摘を自動修正しようとしている
- 指摘対応に仕様変更が必要である
- 指摘対応に変更範囲の拡張が必要である
- 指摘対応に対象外ファイル変更が必要である
- 指摘内容と実装指示書が矛盾している
- レビューSAの重大指摘の対応に仕様変更、変更範囲の拡張、対象外ファイル変更、指示書矛盾、最小修正不可、原因推定が必要である
- 最小修正では対応できない
- 原因を推定で決める必要がある
- テスト期待値変更が必要である
- 同一の停止指摘が連続2回再発した
- 同一の重大指摘が連続2回再発した
- 停止指摘が作業単位化できない（scope外・設計変更要）
- 重大指摘が作業単位化できない（scope外・設計変更要）
- 5回目の自動再修正後も停止指摘または重大指摘が残っている
- 原因特定未了のまま実装サブエージェントを起動しようとした
- サブエージェント起動時に必要なロールプロンプトを渡せない
- レビューSA起動時に `review.md` の本文または要約を渡せない
- 承認済み実装指示書がない
- 対象・範囲・完了条件が未定義である
- テスト条件が未定義で、テスト実行またはテスト前提の実装サブエージェント起動が必要である
- 条件付き事前承認の条件充足を推定で判断する必要がある

```text

prompts/
├─ plan.md
├─ implement.md
├─ audit.md
└─ review.md
docs/
├─ orchestration-process.md
└─ prompt-guide.md
```

### `prompts/`
ロールプロンプトを置く。

```text
prompts/
├─ plan.md
├─ implement.md
├─ audit.md
└─ review.md
```

- `plan.md`: 指示書作成用
- `implement.md`: 実装サブエージェント用
- `audit.md`: 監査サブエージェント用
- `review.md`: PRレビュー相当の品質レビュー用

## `AGENTS.md` の扱い
何を残すか（WHAT）の確定リストはこの文書を正本とする。なぜ・どう書くか（WHY・HOW）は `docs/prompt-guide.md` を見る。

`AGENTS.md` は、親エージェント用の orchestration gate とする。

`AGENTS.md` には、以下を残す。

- 親エージェントの役割
- 実行境界を補完しないこと
- 承認済み実装指示書なしに実装サブエージェントを起動しないこと
- 親エージェントが直接実装・修正・テスト実行・監査・監査後のPRレビュー相当の品質確認を行わないこと
- サブエージェントに渡すべき情報
- 停止指摘 / 任意指摘 / 範囲外指摘の扱い
- レビューSAの重大指摘 / 改善指摘 / 補足 / 範囲外指摘の最小 gate
- レビューSAの重大指摘だけを承認済み範囲内かつ最小修正可能な場合に自動修正候補とすること
- レビューSAの改善指摘 / 補足 / 範囲外指摘は自動修正しないこと
- レビューSAの指摘は親が作業単位化し直してから実装サブエージェントへ渡すこと
- 許可・範囲の根拠は指示書と作業単位化条件に限ること（入力境界ルール）
- 条件付き事前承認は、明示条件を満たすことを推定なしで確認できる場合だけ作業単位化条件として扱うこと
- 作業単位化可否の返却形式（可否 / 理由 / target・scope・done・tests・stop の草案または不足項目）
- 停止指摘は監査サブエージェントの出力から引用し、自動再修正可否の判定根拠として明示すること
- 重大指摘はレビューサブエージェントの出力から引用し、自動再修正可否の判定根拠として明示すること
- PR作成ルール（タイトル・本文・見出しは対象リポジトリの言語規約に従うこと、PR テンプレートがある場合はその構成に従うこと）

`AGENTS.md` には、以下の詳細を含めない。

- 実装サブエージェントの詳細手順
- 監査サブエージェントの詳細分類
- レビューサブエージェントの詳細分類
- 指示書作成の手順
- 自動修正ループの長い説明
- 運用例
- 背景説明の長文

## ロールプロンプトの扱い
サブエージェント起動時は、ロールプロンプトのファイル自動読込を前提にしない。

親エージェントは、サブエージェント起動時にロールプロンプトの本文または要約を起動メッセージで渡す。

```text
プランサブエージェント起動時:
  prompts/plan.md の本文または要約を渡す。

実装サブエージェント起動時:
  prompts/implement.md の本文または要約を渡す。

監査サブエージェント起動時:
  prompts/audit.md の本文または要約を渡す。

レビューサブエージェント起動時:
  prompts/review.md の本文または要約を渡す。
```

## fork_context の扱い
`fork_context` は、親の既存コンテキストを継承するための指定である。

`fork_context` は、リポジトリ上の `AGENTS.md` やロールプロンプトの実ファイル自動読込を保証しない。

`fork_context=true` は便利だが、コンテキストが厚くなり、監査サブエージェントのノイズが増える可能性がある。

`fork_context=false` の場合、必要なロールプロンプト、実装指示書、差分、テスト結果、監査観点、レビュー観点を明示的に渡す必要がある。

## 起動プロンプト標準形
### プランサブエージェント起動
```text
あなたは THE-CAPTION のプランサブエージェントです。
以下の prompts/plan.md の内容に従ってください。

[plan.md の本文または要約]

以下のユーザー依頼と参照文書から、実装指示書の草案を作ってください。

[ユーザー依頼]
[必要に応じて参照文書・承認済み方針]

禁止:
- 実装・修正・テスト実行・監査・レビュー・再修正・許可化
- 対象・範囲・完了条件・品質基準の補完
- 実行許可の生成

出力:
- 境界が定まった実装指示書の草案
- もしくは不足項目
- この草案は実行許可ではない
```

### 実装サブエージェント起動
```text
あなたは THE-CAPTION の実装サブエージェントです。
以下の prompts/implement.md の内容に従ってください。

[implement.md の本文または要約]

以下の承認済み実装指示書に従って、明示された対象・範囲・完了条件・テスト条件だけを扱ってください。テスト条件はテストコマンドまたは `なし（根拠）` とします。

[承認済み実装指示書]

禁止:
- 指示書外の改善
- 仕様変更
- テスト期待値変更
- 対象外ファイル変更
- 便乗リファクタ
- 原因不明の探索的修正

完了時は、変更内容、変更ファイル、実行テスト、テスト結果、初回実装か再修正か、再修正時の指摘、停止理由の有無を返してください。
```

### 監査サブエージェント起動
```text
あなたは THE-CAPTION の監査サブエージェントです。
以下の prompts/audit.md の内容に従ってください。

[audit.md の本文または要約]

以下を非破壊で監査してください。

監査対象:
- 承認済み実装指示書
- 差分
- テスト結果
- 必要に応じて関連仕様
- AI制御文書（AGENTS.md / prompts/*.md / docs/orchestration-process.md / docs/prompt-guide.md）が変更対象の場合は、変更後の当該文書全体

監査観点（AI制御文書が変更対象の場合）:
- 変更後の文書全体が自己無矛盾か
- 変更が他セクションへ追従しきれているか（限定列挙・成立条件・分類基準の追従漏れ）

禁止:
- ファイル変更
- 修正
- テスト実行
- 実装
- 実装指示書作成

出力:
- 結論
- 停止指摘
- 任意指摘
- 範囲外指摘
- 自動修正候補性
- 再監査条件
```

### レビューサブエージェント起動
```text

[review.md の本文または要約]

- 必要に応じて関連仕様
- AI制御文書（AGENTS.md / prompts/*.md / docs/orchestration-process.md / docs/prompt-guide.md）が変更対象の場合は、変更後の当該文書全体

レビュー観点:

- 設計
- テスト妥当性
- 保守性

- 修正
- テスト実行
```

## 完了条件
このプロセス仕様は、以下を満たすとき有効である。

- 指示書作成が実装指示書を作る
- 親エージェントが承認済み実装指示書を管理する
- 親エージェントが直接実装しない
- 親エージェントがSA利用ケース（A〜F）以外でサブエージェントを起動しない
- 実装サブエージェントが implement.md に従う
- 監査サブエージェントが audit.md に従う
- レビューサブエージェントが review.md に従う
- 監査SAへ渡す情報が「承認済み指示書・差分・テスト結果・関連仕様」に限定されている
- レビューSAが監査SAの停止指摘0件後に PRレビュー相当の品質レビューを非破壊で行う
- サブエージェントが AGENTS.md 実ファイルを自動読込する前提にしない
- ロールプロンプトが起動メッセージで明示される
- 起動メッセージに禁止操作が明示される
- 監査SAの停止指摘とレビューSAの重大指摘のみが範囲内自動修正対象になる
- 任意指摘 / 範囲外指摘は自動修正されない
- 改善指摘 / 補足 / 範囲外指摘は自動修正されない
- 自動ループのループ制御・回数カウント・上限判定は親エージェントが管理する
- 監査SAの停止指摘出力は親が作業単位化し直してから実装SAへ渡す
- レビューSAの重大指摘は親が作業単位化し直してから実装SAへ渡す
- 条件付き事前承認は、明示条件を満たすことを推定なしで確認できる場合だけ作業単位化条件として扱われる
- 停止条件に該当した場合は停止する

## 制約
このプロセスは、プロンプト駆動の責務分離である。

以下は保証しない。

- サブエージェントが起動時に `AGENTS.md` 実ファイルを自動読込すること
- サブエージェントがロールプロンプト実ファイルを自動読込すること
- 親エージェントが直接実装できないことのツールレベル強制
- 実行権限のハード分離
- サブエージェント起動仕様そのものの変更

これらを強制したい場合は、別途ツール層または実行基盤側の制御が必要である。
