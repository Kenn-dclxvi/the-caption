# ADR-0005: `target_date` 基準の米国市場日付

## Context

v4 日次台帳の基準日は、日本時間の台帳対象日である `target_date` である。標準実行帯は平日 18:30〜20:00 JST であり、この時間には `target_date` に対応する米国当日セッションはまだ始まっていない。そのため、米国株・コモディティ・FX の採用上限は、実行時刻から再判定するのではなく、`target_date` から一意に決まる直近の NYSE 実取引日を使っている。

検討対象は、米国休場日や大きな値動きがある日に誤った日付を採用するか、不要な確定停止が起きるか、米国株価日と FX 日を分離すべきか、という点である。

## Decision

`us_market_date` の決め方は維持し、`DAY` の基準だけを出力の正本（[ADR-0002](./ADR-0002-ledger-native-ssot.md)）へ移す。本文末尾の Deferred Alternative を採用済みへ変更した。

- `target_date` を JP 台帳対象日の正典とする。
- `us_market_date` は、`target_date - 1日` 以前で直近の NYSE 実取引日とする。
- 米国株・コモディティ・USD/JPY は、すべて同じ `us_market_date` を採用上限とする。
- ローカル履歴に `us_market_date` より後の行が存在しても、その `target_date` の計算には使用しない。
- 値動きの大小、曜日、米国休場、日本休場だけを理由に配信または確定を止めない。
- 米国株価用の日付と FX 用の日付は、現時点では分離しない。
- `DAY` 基準の移行に伴うコード変更は本 ADR の範囲とする。既存メールと `daily_metrics` は再生成せず、`integrity_status = VERIFIED` の確定台帳は書き換えない（詳細は Adopted Alternative）。

`DAY` は「前営業日の確定台帳からの円建て評価額変化」とする。前日側は値段と為替の両方を前営業日の正本に記録された確定値で揃え、当日側はその `target_date` で確定した値段と為替を使う。数量は当日値のみを用いるため、買い増しによる評価額増加は `DAY` へ混入しない。

この定義では、同じ `us_market_date` を参照する複数の `target_date` で原資産騰落を再計上しない。米国休場を挟んで値段も為替も動いていなければ `DAY=0` となる。前営業日の正本が存在しない場合（正本の欠落区間、および資産別の為替を持たない v3.5 以前の台帳）は、取得元履歴の前セッション比へフォールバックする。

いつ確定したかは参考情報であり、確定値そのものを基準とする。期待日の値段が取得元に無く前営業日の正本から確定値を継承した場合、`source_date` はその確定日を示す。継承の要件は ADR-0002 の Guardrails に従う。

## Current Behavior

`TimelineController.get_us_market_context()` は、`target_date` の暦上の前日を `calendar_date`、その日以前の直近 NYSE 実取引日を `trading_date` として返す。`UniversalIngester` は `trading_date` を `us_market_date` として米国株・コモディティ・FX の履歴を同日までに制限する。このため、後日履歴が更新されても、その `target_date` から見て未来の米国データは混入しない。

取引日と確定判定は別の概念とする。`trading_date` は対象となる米国セッションの日付であり、`source_date` は実際に採用した原資産価格行の日付である。データを取得した日時や後日更新した日時は、どちらの日付にも置き換えない。必要な価格行と FX 行が期待日へ到達し、終値確認を通過したかは `pricing_status` で表す。

`DAY` 基準の移行前は、同じ `us_market_date` を参照する複数の `target_date` で米国資産の `DAY` が同じ値になっていた。たとえば 2026-06-19 と 2026-06-22 は TSMC `+6.935%`、Silver `-6.282%` を同じように表示し、2026-07-03 と 2026-07-06 は TSMC `-2.267%`、Platinum `+1.743%` を同じように表示した。移行後は前営業日の正本を基準とするため、これらの再計上は起きない。

USD 建て資産の `DAY` は、値段と為替の両方を前営業日の正本と当日で対応させた円建て評価額の変化である。原資産価格が動かず為替だけが動いた場合も、その寄与を `DAY` に計上する。これにより資産別および合計の `DAY` が評価額の実差と一致する。

## Observed Evidence

実運用ログと保存済み `daily_metrics` では、次の動作を確認した。

| `target_date` | 採用した `us_market_date` | 実際の動作 |
| :--- | :--- | :--- |
| 2026-07-17 | 2026-07-16 | TSMC `-2.322%`、Gold `-1.444%` などを含め、米国系資産はすべて `PRICED`。18:30 に確定配信。 |
| 2026-06-22 | 2026-06-18 | Juneteenth と週末を越えてロールバック。TSMC `+6.935%`、Silver `-6.282%` でも米国系資産は `PRICED`。18:30〜19:00 の暫定配信原因は投資信託2件であり、19:15 に確定配信。 |
| 2026-07-06 | 2026-07-02 | Independence Day 振替休場と週末を越えてロールバック。米国系資産はすべて `PRICED`。18:30 に確定配信。 |
| 2026-05-26 | 2026-05-22 | Memorial Day を越えてロールバック。`MISSING=0`、`STALE=0`。 |
| 2026-05-04 | 2026-05-01 | 日本休場日でも米国系資産は `PRICED`。`STALE` は投資信託のみ。 |

米国株価日と FX 日を分離して、NYSE 休場中も後続の FX 行を採用した場合の全体評価額差を、後日保存された履歴から概算した結果は次のとおりである。履歴値は後日更新され得るため、これは厳密な当日再現ではなく判断材料である。

| `target_date` | 現行 FX | 後続 FX | 全体評価額の概算差 |
| :--- | :--- | :--- | ---: |
| 2026-05-26 | 2026-05-22: 159.018 | 2026-05-25: 158.946 | 約 `-116円`（`-0.0007%`） |
| 2026-06-22 | 2026-06-18: 160.600 | 2026-06-19: 161.289 | 約 `+1,213円`（`+0.0073%`） |
| 2026-07-06 | 2026-07-02: 162.539 | 2026-07-03: 161.449 | 約 `-1,822円`（`-0.0111%`） |

観測範囲では、標準実行帯に米国市場の `market_state=PRE` が原因となって米国資産が誤って `STALE` になった事例はない。したがって、実在しない動作を前提とした追加ブロックは導入しない。

## Blocking Boundary

- 資産一覧が空、台帳合計が不正または0以下、確定台帳や必須日次データを保存できない場合は、配信を停止する。
- 必須市場資産が `MISSING` または `STALE` の場合は、対象資産を1回だけ選択更新する。
- 選択更新後も未確定なら、件名末尾に `○` を付けた暫定メールは配信するが、CompletionLock は記録しない。
- `MISSING` と `STALE` がなくなった実行だけを確定配信とし、CompletionLock を記録する。
- 大幅な上昇・下落、月曜日、米国休場、日本休場は、それ自体をブロック条件にしない。

## Accepted Limitations

- NYSE カレンダーを利用できない場合のフォールバックは週末だけを除外し、平日の NYSE 祝日を認識しない。その場合は存在しない取引日を期待するため、通常は価格または FX が `STALE` となり確定配信を防ぐが、カレンダー利用不能そのものを明示的に hard block する実装ではない。実運用での発生は未観測であり、追加 hard block は将来の堅牢化課題とする。
- 休場日用プロンプトは「価格変動の主因は FX のみ」と指示する。`DAY` 基準の移行により為替寄与が `DAY` へ計上されるようになったため、この指示と台帳の整合は回復した。

## Adopted Alternative

Deferred Alternative として保留していた「前回の JP レポートからの円建て評価額変化」を採用した。採用時の要件と実装状況は次のとおりである。

- `us_market_date` は従来どおり値段と為替の共通の採用上限とする（`stock_date` / `fx_date` の分離は行わない）。
- 前営業日と同じ値段であれば原資産騰落を再計上しない。
- 為替だけ更新された場合は為替寄与を `DAY` に計上する。
- 値段も為替も動いていなければ `DAY=0` とする。

値段だけを先行して正本基準へ移すと、為替が当日値のまま残り評価額の変化を `DAY` が取りこぼす。実測では資産別で最大 `1,000円`、合計で `4,331円` の差が `total_diff_jpy` に説明されない形で残った。このため値段と為替は一体で移行する。

過去の保有数量を正確に復元できないため、既存メール・`daily_metrics` は再生成しない。確定台帳は `integrity_status = VERIFIED` の日を書き換えない（ADR-0002）。

## Non-goals

- 米国市場の取引日とデータ取得日時または確定判定を同じ概念として扱うこと
- 実行前に将来の `target_date` の確定可否を判定すること
- 値動きの大きさを異常値ブロックへ追加すること
- 米国株価日と FX 日を分離すること
- プロンプト本文を変更すること
- 期間騰落（`WTD` / `MTD` / `YTD`）の基準を正本へ移すこと（ADR-0002 の Open items で扱う）

## Consequences

`target_date` ごとに、その時点で確定している直近米国セッションだけを再現できる。米国休場日にも不要な停止を増やさず、既存の暫定配信と CompletionLock がデータ未確定を扱う。`DAY` 基準の移行により、休場期間中の為替だけの変化と前営業日からの日次差を表現できるようになり、資産別および合計の `DAY` が評価額の実差と一致する。一方、`WTD` / `MTD` / `YTD` は取得元履歴の期間起点を基準とするため、`DAY` の累計とは一致しない。
